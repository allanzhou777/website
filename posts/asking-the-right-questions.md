# The Hard Part Is Still Knowing What to Ask

*March 15, 2026 · note · #ai #tools #thought*

I use agents for most of my coding now. Cursor, Claude Code, and whatever comes next have changed the feel of building things for me: once I can describe a contained task clearly, getting to a first working version is much faster than it used to be.

That has not made the work effortless. It has mostly made the real bottleneck harder to ignore.

In research, the difficult part is often deciding which question is worth asking. Once the question is precise enough, the experiment, implementation, and analysis can become almost mechanical. But a clean answer to an unimportant question is still not very useful. I think building with AI has the same shape.

Nimit Sohoni, an AI researcher and former Citadel quant, puts it more bluntly in [a conversation on research taste](https://www.youtube.com/watch?v=_jECS37M3dQ): “90% of the battle in research is actually finding the right problems.” His point is not that execution is easy. It is that a problem has to be meaningful, interesting, and scoped tightly enough to make progress before execution can matter.

An agent can write a lot of code quickly. It can also confidently build the wrong abstraction, optimize the wrong metric, or solve a problem that did not need solving. The leverage only shows up after I have done the less visible work: understanding the system, choosing the constraint that matters, and breaking the work into pieces that can actually be checked.

This is why I do not think becoming an expert in every AI tool is the point. I try new features when they clearly help, but I do not want my workflow to depend on memorizing the current interface. The tools will keep changing. The useful habits are more durable: write down what success means, make assumptions explicit, ask for a small testable change, and inspect the result rather than trusting a polished explanation.

There is a loose parallel here with Sutton's [Bitter Lesson](http://www.incompleteideas.net/IncIdeas/BitterLesson.html). In AI research, methods that can scale tend to outlast elaborate hand-built systems. For AI tooling, I think the analogous mistake is spending too much time perfecting a setup and too little time thinking about the problem. Configuration can feel like progress because it is close to the work. It is not the work.

The part I want to get better at is judgment: noticing what is unclear, asking a question that reduces uncertainty, and recognizing when a fast answer is not a reliable one. Better tools make that skill more valuable, not less.
